# 2026-10-25 编码器微调与无标签数据对照

最终说明和本地验证见 [实验报告](../../docs/U_SSL_20261025.md)。已评分对照保持原0.49，不覆盖旧文件。

大文件根目录：`D:/huawei2026-experiments/u_ssl_20261025`。依赖既有比赛原始标注/U及各整房间教师快照，路径集中在`ssl_common.py`、`prepare.py`。

流程（项目虚拟环境执行，逐步完成后再开始下一步）：

1. `prepare.py --room all`：审计U原始记录；缓存四视角冻结前缀。U没有标签，不构造伪标签。
2. `train.py --room all`：监督、源视图一致性、U视图一致性，共30次。
3. `train.py --room all --methods paired,paired_u`：追加同房间0/1配对对照20次。
4. `evaluate.py`、`matched.py`：选择快照后的整房间比较，以及固定120步比较。外层房间不参与该代理模型的训练和校准，但这些房间历史上用于研究，不构成全新的盲测。
5. 检查全部结果再保存D盘`selection.json`；当前选择paired、0.5参数插值、双种子、full。选择依据保存在同文件reason内。
6. `export_candidate.py`：原0.49图复用冻结前缀，新增更新编码器后缀；逐条原始输入核对960窗。
7. `tools/check_candidate.py D:/huawei2026-experiments/u_ssl_20261025/export`：独立CPU进程资源与数值检查。
8. `publish.py`：仅在以上检查通过后复制一个最终ONNX至C盘，登记为未评分并写报告。

各次fit保存源样本抽样哈希，确保主要标签抽样一致；paired方法额外读取0/1对，不能和不配对方法声称完全等标签预算。训练投影器不进入提交图。最终方案未使用U自监督，其对照结果保留，不能把本轮收益归因于U。

禁止把960窗来源准确率视为隐藏平台成绩，或根据同一批来源数据的高分选择最大更新强度。平台目标0.52必须由平台实测确认。
