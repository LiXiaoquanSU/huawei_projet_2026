## 接口

- 训练类 `RoomSenseModel`：frames `[B,600,1,3,1024,2]`，intervals `[B,600]`，输出 `[B,5]`。
- 提交封装 `SubmissionModel`：frames `[600,1,3,1024,2]`，intervals `[600]`，输出 float32 `[5]`。
- 输出为0至4人的logits，不在模型内做softmax或argmax。
- 从原始CSI窗口拆分实部/虚部，ATI取同一窗口并复制、将末尾设置为0。其余推理预处理全部进入ONNX，平台不需要额外Python处理脚本。

## CSI表示

1. 用实部、虚部计算功率 `p = real² + imag²`，转换为 `0.5*log(1+p)`，在高幅度时接近对数幅度，压缩尺度并稳定处理零值。
2. 基线不使用原始相位。对公共相位旋转不敏感，但会丢失相位携带的信息；相位是否有增益留待后续受控实验，不能事先假定。
3. 每32个相邻子载波按有效值平均，将1024压缩成32个频率组。功率低于 `1e-8` 的输入按无效值处理；不从验证集推断固定频点位置。全零频率组安全输出0。
4. 时序支路：每个Rx×频率组减去该600帧窗口的时间均值，再按该接收天线的窗口动态RMS归一化（下限0.02），裁剪至±8。
5. 使用窗口自身进行归一化，不拟合全数据或验证集统计。离线估计整段600帧，无因果实时性要求；不得使用窗口外帧。

## ATI与动态特征

- 只读前599个真实间隔；最后的补零无论数值为何均被忽略。
- 微秒换算为秒，将相邻帧的对数幅度差按 `0.005 / clip(dt,0.001,0.1)` 缩放，再裁剪极值。无有效间隔或频率组的差分置零。
- 这是稳健的相邻变化特征，并非对长间断的精确连续时间重建。较长间断的信息仍通过时间特征保留，不能恢复缺失帧。
- 每帧提供：对数间隔、超过20毫秒的间断标志、有效间隔标志；与后一个帧对齐，首帧填0。
- 网络仍在帧索引上卷积，ATI帮助区分时间差异，但不保证完全时间不变。第一版不做均匀时间插值，避免给长间断编造信号。
- 阈值是固定工程常量，未通过验证集拟合。20毫秒标志不用于删除任何记录。

## 两个支路

时序输入 `[B,195,600]`：

- 96通道：3根Rx×32频率组的归一化对数幅度。
- 96通道：时间修正的相邻幅度差，额外固定缩放、裁剪以适应输入数值范围。
- 3通道：上述ATI信息。

时序网络：

```text
Conv1d(195 → 64, kernel=5, stride=2)
GroupNorm + SiLU
5个残差块：Depthwise Conv1d(kernel=5, dilation=1/2/4/8/16)
              → Pointwise Conv1d(64 → 64) → GroupNorm → SiLU → Dropout
时间维 mean / std / max 聚合 → 192维
```

GroupNorm不累计跨房间的BatchNorm运行统计。局部卷积感受野约253个原始帧，再通过全局聚合利用完整600帧窗口；实际时间跨度随ATI变化。

统计支路17维：每根Rx的平均对数幅度、频率/时间总体标准差、动态RMS、时间修正差分强度（共12维）；有效间隔均值、变异系数、最大间隔、长间隔比例、实际窗口时长（共5维）。对部分小量做固定缩放或log1p压缩，再通过 `Linear(17→32) + LayerNorm + SiLU`。

融合：`192 + 32 → Linear(224→64) → SiLU → Dropout → Linear(64→5)`。

保留静态统计是为了避免把潜在的人数信息全部归一化掉；同时它也可能编码房间背景，因此后续必须对比有/无统计支路，而不是预先认定有益。

## 验证与交付

模型代码：`roomsense_model.py`。验证命令：

```powershell
.\.venv\Scripts\python.exe -X utf8 validate_model.py
```

脚本检查：批量GPU反向传播、有限参数梯度、GPU/CPU数值一致性、末尾ATI补零不影响结果、公共90度相位旋转不影响结果、ONNX合法性、正常训练窗口/留出房间窗口/长间隔窗口/全零输入的CPU推理。

CPU计时与内存使用独立子进程，只加载ONNX Runtime和验证输入，不加载PyTorch或CUDA。每例预热后计时20次，4个CPU线程；峰值工作集和提交内存包含运行时及输入加载。结果见 `artifacts/model_design/*validation.json`。本机测试不能代替评测服务器测试。

导出必须使用 `export_submission(model, example, path)`，设置 `optimize=False`。本环境默认ONNX导出优化曾移除方差计算中很小的稳定项，使全零输入的结果与PyTorch明显不同；该设置保留稳定项，之后仍由CPU ONNX Runtime执行并验证。后续更新依赖后应重复验证。

生成的 `architecture.onnx` 仅证明结构和接口可用，没有经过正式训练，不作为竞赛答案提交。

2026-10-18 实测：101,317个参数，ONNX 1,149,796字节；4种输入每种20次CPU推理的平均耗时范围0.00956–0.01293秒，最高单组P95约0.01984秒。独立CPU进程峰值工作集161,685,504字节，峰值提交内存785,166,336字节。上述数值和GPU训练路径检查全部通过；未测量正式训练后的分类准确率。
