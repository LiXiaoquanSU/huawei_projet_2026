# 全对称12视角候选：取消类别硬保护并共享预处理

**后续实测更新：用户反馈平台0.41，低于两份保护版0.47。以下保留原实验过程，不再作为提交推荐。新复盘见 [0.41复盘](REVIEW_041.md)，其中发现固定偏置跨历史checkpoint迁移会改变策略排序。**

## 文件与结论

已测文件 `models/tta_policy_20261024/01_symmetric_unprotected.onnx`，**39.54 MB**，SHA256 `0d641389b68a658bfcd6f53bf2b535bf08ec33f953768d2ef4a080fcaf993b98`，用户反馈平台0.41。

沿用0.44/0.47的全部推理权重及固定偏置，不重新训练、不重估先验。新模型取消0/2硬保护，对所有人数都汇总全部6种接收通道排列及2种时间方向。与原0.47带保护版相比，整个决策函数都采取对称平均，而非只在部分预测上平均。

两种子三房间代理均值28.53%，高于轻版代理23.84%、完整版代理24.92%；宏召回同步提高。**e1压力测试所有策略仍0%，所以没有证明跨所有房间都有效，不保证老师平台超过0.47。**

## 题目依据

重新阅读本地 [老师题目](reference/problem_statement.pdf) 第2–4页：目标是泛化到无标签的不同物理房间，测试布局来自训练布局家族；第6页明确每个600帧样本内人数恒定；第7–8页给出1Tx/3Rx/1024子载波、80MHz、ATI单位和最终0补齐、固定输入/输出以及CPU/体积约束。

因此反向查看同一固定人数窗口有依据，接收通道重编号不会增加或减少人数。但老师并没有说天线编号随机，也没有保证任何变换都无损，不能把推理增强收益归因于一个未经确认的隐藏条件。

我们的有标签数据每个已知布局只有一个房间，局部留房间同时留布局，和题目的“布局家族内跨物理房间”并非完全相同。这个验证局限是此前本地与平台排序不一致的重要候选解释，不能由本地涨幅直接预测平台涨幅。

## 为什么不再只增加参数

原0.47沿用相同权重，通过观察不同视角和限制聚合范围提高分数。我们这次测试的是硬保护是否也锁住错误，而不是假设0/2总最可靠。此前扩宽、密集滑窗和整体联合训练未有稳定收益，因此优先改进有依据的推理流程。

同时保持少量固定对照，避免在小开发集上任意搜索五维偏置。全部策略共享同一个队友偏置值，不增加U数据、不拟合新类别先验。其上游估计方法未知，因此不能宣称整个校准管线从未利用过这些房间信息；能确认的是本轮没有用验证标签拟合偏置。

## 7个预先定义的规则

- light：复现4视角保护版。
- full：复现12视角保护版。
- unprotected：始终平均12视角，不锁定0/2。
- trimmed：保留原保护，其余类别对6个时间平均视角逐类去最大/最小，再平均。
- geometric：保留原保护，其余取几何平均。
- cyclic：保留原保护，其余采用三个循环天线排列的时间平均。
- consensus5：保留保护，只有至少5/6视角同意另一个聚合赢家且概率间隔至少0.20时才允许改动。

没有对这些规则的权重或阈值作网格搜索。选取规则预先写在D盘plan.json：挑战者必须同时超过light/full中较强者的平均准确率、不降低宏召回，再按min(房间均值,宏召回)及最差房间排序。此次只有unprotected满足条件。该规则族本身仍是开发选择，不是独立测试。

## 实现变化与运行成本

原完整版每个天线排列重复原始CSI预处理。新实现只对正向、反向原始帧各预处理一次，再通过已核验的特征索引和相位正负变换生成6种天线排列；共享原网络，批量计算12个视角。

图没有引入新的学习参数。幅度每接收通道块重排，相位对按实际天线对映射，反向相位对的sin特征变号；每接收通道的统计量一同重排，时间信息保持相应方向。先以原始CSI重新预处理核对该特征规则，再测批量实现是否复现两份实际0.47，避免为了优化速度改变信号含义。

新文件39,538,097字节，相对原完整版83.68MB更小；CPU四线程三种输入最慢均值0.3624秒，相对原完整版约0.617秒更快，但比原轻版约0.173秒更慢。峰值提交内存1.989GB。ONNX18、内置权重，接口保持frames[600,1,3,1024,2]、intervals[600] -> logits[5]float32。

## 验证

1. 全部177个推理参数/缓冲量与实际0.44一致（112个原float32与65个按相同规则取整的大张量）；4个未在推理使用的motion辅助张量不影响输出。
2. 批量实现复现原light/full：33个输入最大概率误差0.00064435。这些输入只作数值检查，不算独立准确率。
3. 新导出ONNX与Torch候选：30个真实窗口最大概率误差0.00001166；另普通/异常间隔/全零3输入在独立CPU进程检查。
4. 实际导出ONNX对4个输入×6种天线排列×2种时间方向共48次检查，类别全部一致，最大概率变化0.00000006。这证实测试样本上的对称性，并非隐藏集准确率。
5. 原0.44和两份0.47哈希保持不变。新模型不继承0.47分数。

## 提交判断

这是一个有代理对照支持、但仍具风险的候选。它可能纠正保护门锁住的错误，也可能改坏原本正确的0/2；[TTA聚合研究（ICCV2021）](https://openaccess.thecvf.com/content/ICCV2021/html/Shanmugam_Better_Aggregation_in_Test-Time_Augmentation_ICCV_2021_paper.html)说明聚合并非只纠错不退步，但不证明我们这里去掉保护必然更好。
