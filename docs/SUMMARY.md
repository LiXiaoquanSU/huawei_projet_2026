# 项目简要总结

## 任务与模型

根据 WiFi 信道信息 CSI 和采样时间 ATI，判断房间有 0、1、2、3、4 人。输入为 `frames: float32[600,1,3,1024,2]` 和 `intervals: float32[600]`，输出 `logits: float32[5]`，下标对应人数。

当前保留同一个约 1971 万参数的结构，分四条路线：

1. 静态幅度：观察不同子载波的信号分布。
2. 动态幅度：观察窗口内的信号变化。
3. 相对相位：观察天线间关系，减弱共同相位偏移的影响。
4. 时间注意力：结合采样间隔观察跨时间关系。

四路特征经过门控与分类头融合。另有“是否有人”和逐级人数判断，并用信号相关性辅助训练。这些是信号特征与人数子任务，**不代表模型已经测出了房间面积或真实人物轨迹**。

## 训练与平台结果

48 条有标签记录切成 960 个不重叠窗口，按人数、房间加权采样。最佳版训练 5 轮，使用 AdamW。SAM 版保留相同结构和预算，每次更新增加一次权重扰动后的梯度计算，尝试改善泛化。

| 版本 | 官方平台结果（用户报告） |
|---|---:|
| 较早版本 | 0.22 |
| 队友版本 | 0.31 |
| 6 MB 融合版 | 0.18，已撤回 |
| 82 MB 结构化版 | **0.37，当前保留基准** |
| SAM 版 | **0.32**，已成功评测，低于基准 0.05 |

后续完成 22 次开发训练及 4 次固定参数平均评估。增加关系分支、延长至 12 轮、错位窗口、参数平均均没有稳定改善。SAM 三个留出房间均值从 28.56% 升至 32.19%，但整条记录留出从 37.73% 降至 35.45%，最终平台也降至 0.32。保留原 0.37 版，SAM 不作为升级推荐。

此前提交 47074 的下载错误单独保留为历史事件；成功评测的新提交编号未提供，不能把 47074 填成 0.32 的提交编号。平台只有总分，尚不能确定分数下降的具体类别或原因。后续分析见 [改进方向](IMPROVEMENT.md)。

开发数据被重复用于比较，本地分数不能直接预测官方隐藏测试成绩。当前停止扩展，保留两份模型与原始证据。

## 代码与复现

| 文件 | 内容 |
|---|---|
| `src/model.py` | 四路线网络与人数子任务 |
| `src/features.py` | 原始数据预处理、ONNX 输入输出封装 |
| `src/utils.py` | 窗口读取、训练损失及表格工具 |
| `src/train.py` | 原 5 轮训练和 SAM 训练入口 |
| `src/export_model.py` | 从保存权重导出新文件，拒绝覆盖已有文件 |
| `src/check_model.py` | 文件完整性、嵌入权重及 CPU 推理检查 |

本次仅整合原定义、移除历史依赖，未重训。两份权重在旧／新定义上的特征和原始输入输出均完全一致，记录见 `checks/cleanup_equivalence.json`。训练代码改为直接按保存清单提取特征，不再依赖旧实验缓存；历史精确脚本与缓存仍在归档中。

原环境为 Windows、Python 3.13、PyTorch 2.9.1 CUDA 12.6。当前 `.venv` 保持不变；原完整版本锁定表在 `_archive/history_20261019/requirements-lock.txt`。

本地参考限制为单个嵌入权重 ONNX 小于 100,000,000 字节、CPU 平均每窗口小于 0.7 秒、内存小于 6 GB，原指南在 `docs/reference/`。两份模型均为 82,057,525 字节；服务器表现仍以实际评测为准。

参考思路：[DASECount](https://arxiv.org/abs/2211.10040) 的幅度／相位特征路线、[CORN](https://arxiv.org/abs/2111.08851) 的条件人数判断、[SAM](https://arxiv.org/abs/2010.01412) 的训练优化。这里只采用部分思路，不能沿用论文中的准确率。
