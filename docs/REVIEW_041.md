# 无保护版0.41：复盘与下一轮方向

用户反馈：全对称12视角无保护版平台0.41；SHA256为 `0d641389b68a658bfcd6f53bf2b535bf08ec33f953768d2ef4a080fcaf993b98`。保留原文件，更新侧车、注册表及成绩表；原两份0.47不变。提交编号未知。不再将此文件列为下一份推荐提交。

## 哪个假设失败了

“标签在通道重编号下不变”不等于“一个已训练的、对通道顺序敏感的网络在任意排列下都同样可靠”。无条件平均可以稀释原视角的正确证据。0.47完整版同样使用12视角但带0/2保护，当前0.41与它相比是退步，支持保留保护作为后续基准。没有隐藏逐样本结果，无法确定损失分别来自0人、2人或具体房间，也不能推出所有软门控都不如硬保护。

这不是模型参数不足的证据。候选冻结原推理权重及偏置，改变聚合规则，同时改为共享预处理、批量推理。此前数值探针降低了实现错误的可能性，但它们并非对所有输入的等价证明；不能把6个百分点全部精确归因到某个单一原因。

## 更关键：原来的本地筛选不够可信

重新利用之前缓存的留房间预测，未增加训练或拟合偏置。结果见 `checks/unprotected041_review.json`，复现入口 `tools/review_unprotected041.py`。

- c1两种子带固定偏置的保护版全部240个窗口均预测2人；无保护版只改动1个窗口。这是输出塌缩，不是已解决跨房间计数。
- 所有7组房间/种子对照，带该偏置的两种策略都没有预测1人。不能把这个现象转移到真正的0.47模型或隐藏测试。
- a1种子2026贡献了本地看似最大的收益：保护版20.42%、无保护版36.67%，增加16.25个百分点。但它将117个原本预测2人的窗口改成4人，不能据此证明普遍纠错。
- 相同a1/种子2026，**仅作为诊断去掉固定偏置**后，保护版22.92%、无保护版16.25%，排序反转。这里没有搜索新偏置，也没有据此导出零偏置提交模型。
- e1带偏置两版仍0%；零偏置两版虽为33.33%，但全部预测1人，仍然不能称为有效泛化。

队友偏置与实际全数据模型是一个经平台验证的组合。历史代理checkpoint则来自其他训练子集，直接套用这组偏置，没有验证其适用性。固定偏置使方法比较一致，但不保证比较能代表实际提交网络。之前把这种比较作为导出选择的主要依据，证据不足。

注意：零偏置诊断没有否定实际0.44偏置。真正的0.42到0.44已获平台收益；这里发现的是**校准不能未经检验跨checkpoint迁移**。同样不能从这里推断老师测试集类别比例。

## 下一轮实验应怎么改

优先检验“保留0.47的可靠判断，加入不同结构的补充证据”，而不是继续删除保护或扩大同一个模型。

1. **重新建立模型与校准配套的对照。** 每个代理模型的校准只能来自训练侧按源记录分组的内部留出预测；外层整房间留出仅作评估。报告零偏置和该模型自己的校准结果；队友固定偏置仅作敏感性对照。训练侧划分需要记录人数覆盖；缺少的类别无法可靠估计校准时必须报告，不可用外层标签补齐。由于已知房间/类别强混杂，此流程也不能保证代表老师布局内跨房间测试。
2. **主候选是有保护的异构互补。** 保留0.47轻版为主路，增加历史上下文事件结构为补充路。先用各自独立的训练侧校准，比较它们在外层错误是否互补，再决定是否融合。不能简单复用0.44偏置给另一个结构，或对已经校准的输出再加一次相同偏置。
3. **先测试固定的保守融合，再考虑学习门控。** 第一项保留主路0/2判断，只对其他样本融合；第二项只在双方预测一致时调整置信度，作为实现/校准对照。后一项若不改变类别，本来就不会提高argmax准确率，不能包装成升级。若学习门控，其训练样本必须是各基础模型未见过的记录预测，并在内层选择；严禁用原模型训练准确率训练“可靠性检测器”。
4. **训练改进作为独立消融。** 只对经过实际验证有效的时间反转、少量通道变换做训练与一致性约束；保留原方向的有标签人数损失，避免强迫所有视角均匀。该项需要重新训练、重新校准，不能继承0.47分数，也不要和融合同时改动后笼统归因。
5. **提交筛选增加否决条件。** 不以房间平均值单独排序。报告每类召回、各房间预测分布、源记录级纠错/改错和不同种子的变化。c1单类塌缩、e1完全失效的模型不能再被描述为已证明稳健提升。数据覆盖不足时明确证据不足，不靠多次扫阈值消除警报。

这是一份重新设计的实验方案，本轮只做记录和诊断，没有新增训练、没有生成下一份候选、没有自动提交。当前实际推荐基准仍是两份0.47。小版因资源开销较低优先保留，不代表其隐藏准确率已证明高于大版。
